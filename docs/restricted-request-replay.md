# 账号受限后的请求等待

当模型上游明确返回 **HTTP 403 / code 11140** 时，Chat Completions、Responses 和
Anthropic Messages 的当前请求会先停止调度受限账号，持久化原有停用标记，再等待
**两分钟**，最多向另一个符合现有调度规则的账号尝试一次。此行为不代表上游已解除
限制，也不保证降低账号风控风险。

- 等待的是这条 HTTP 请求。受限账号保持停用，不会因两分钟到期而恢复。
- 没有其他合格账号、已用完额外尝试预算，或者本请求已经接受上游成功响应时，
  不执行这次延迟换号，直接返回拒绝。等待结束后仍会重新检查账号资格与重试预算。
- 等待期间释放账号并发名额、凭据锁及上一尝试的响应体；不预占下一账号或额外重试
  名额。整请求准入、API Key 并发名额和输入内存预算继续持有，保留现有容量上限。
- 该次换号的请求正文及会话/轮次/消息标识保持一致，正常的 Prefix Affinity 资格与
  后续绑定规则不变。无额外模型探测。
- 下一账号再次失败就结束这条请求，停止继续遍历账号池，包括下一次返回 401/429
  的情况。其他新请求照常使用现有调度器。
- 客户端断开、超时或服务关闭会取消等待/正在进行的后续尝试；没有后台队列，不在
  客户端断开后继续重放，也不在重启后恢复未完成请求。
- 上游已经开始流式输出后遇到 11140，按协议报告错误，保留业务码，不延迟换号。

## 客户端可见行为

流式请求等待时立即发送 SSE 注释，并按照现有流心跳间隔持续保活；下一账号等待
响应头时仍有心跳。SSE 注释不包含模型输出，不计入首个有效增量或积分。

心跳已经提交 HTTP 200 后若后续仍失败，使用对应流协议的终止错误：Chat 的
`data: {"error": ...}`、Messages 的 `event: error`、Responses 的
`event: response.failed`。保留上游业务错误码与脱敏后的详情，不补发 `[DONE]`、
`message_stop` 或 `response.completed`。

未发送心跳的拒绝和非流式请求仍返回真实 HTTP 错误状态/JSON。非流式请求在两分钟
等待期间不发送正文；客户端和反向代理的等待超时需覆盖这段时间及随后的推理耗时。
SSE 心跳也不能延长客户端自行设置的整请求总期限。

本功能固定等待两分钟，无新增生产配置字段。原 11128 的如实返回且不换号、不停用
账号行为不变，普通 401/429 的既有处理仅在已经执行该次延迟换号时停止继续代偿。
明确拒绝不虚构扣费，实际成功请求仍以原有 usage/WAL 流程结算。

## 离线验证

`restricted_replay_test.go` 使用客户端和上游两层 `httptest.Server`，覆盖三协议、两站、
流式/聚合、两分钟默认值及缩短后的真实等待、工具和会话字段不变、后续亲和、两次
成功的实测积分与 WAL 重放、再次受限后停止、候选/预算不足、等待取消、等待时释放
账号名额、下一账号资格变化、下一账号响应头等待时断连以及部分输出后的11140。

这些测试没有调用真实上游，也不构成实际 Codex/DSH 客户端端到端或解封验证。
