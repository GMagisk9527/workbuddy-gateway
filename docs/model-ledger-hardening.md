# 模型标识与账本故障保护

## 模型标识预算

Messages、Chat、Responses 与本地 count_tokens 在记录模型名之前执行共同校验：
最多 256 字节、有效 UTF-8，不包含空白、控制字符或 Unicode 格式控制字符。
省略或空字符串保留原默认模型行为，错误提示不会回显不合法的模型名。
合法且未出现在目录中的模型仍可透传，未改为模型目录白名单。

进程模型统计最多 1024 项（包含一个其他模型合计项）。达到上限后，新标识的统计合并到该固定项，
已有模型统计继续累计。单账号的模型状态也最多 1024 项，恢复旧快照时同样限制条目数与名字。
达到上限时先淘汰最早的非阻断观测；已记录的有效冷却、探测等待和额度阻断不会为新标识而被淘汰。
如果全部条目都处于保护状态，该账号暂时不接收新的未跟踪模型，仍可服务已跟踪模型，其他账号也可继续调度。
保护到期或额度恢复后，空闲条目可再次被替换，避免把账号永久锁死，也避免填满缓存淘汰限流/额度保护。

## 受管 Key 的持久化调用凭据

在实际提交受管 Key 的上游尝试前，网关先同步追加 `begin` WAL 记录，标识 Key ID 与 attempt ID。
写入失败则不调用模型。成功结算追加原费用记录并关闭凭据；明确未计费的失败追加 `cancel`。
原有兼容旧 Key 的调用行为不变，不记录请求正文或凭据明文。

快照会保留仍在途的凭据。重启时，未完成的凭据表示消耗无法确认，触发持久化 `Incomplete` 保护。
即使 WAL 写入和故障状态文件写入同时因磁盘满而失败，调用前已同步的凭据仍会在恢复时阻止有限额 Key 被当作零消费放行。
因此进程在受管调用进行时被强杀，也可能需要核对该调用后人工恢复；正常排空并完成结算的重启不会触发此保护。

追加失败后停止该账本继续写入或压缩，尽力同步故障标记，不把失败写入发布成“已结算”内存增量。
失败 attempt 不占用成功去重项；写入状态不确定时也不会直接重试可能已写入的记录。
恢复会检查快照后的第一个序号以及 WAL 全部行的连续性，重复、倒序、缺口拒绝以部分消费历史启动。

代价是每个受管上游尝试增加一次调用前的小型 WAL 写入和 fsync，明确未计费的结束也需要关闭凭据。
该开销换取故障后可识别的不确定消费；费用数值、日/月归属、usage 缺失策略和 SSE 协议不改变。
升级前应备份 Key、WAL、快照与状态文件；降级软件也应使用配套备份，旧版本不理解新增调用凭据。

磁盘故障后先停止新调用、备份所有账本文件并恢复可写存储，再按上游记录核对未完成 attempt，
使用完整可信账本恢复。不能只删除 `Incomplete`、WAL 或快照来恢复放行，这会把未知消费当成零。

## Key 管理操作

创建先同步独立鉴权开关，再同步 Key 表，落盘失败撤销未返回的 Key。
轮换、编辑、启停和删除在相应锁内写盘；失败恢复原哈希、前缀、配置、索引及匿名归档。
因此客户端不会因一次失败的轮换丢失仍可用的旧 Key，也不会观察到编辑的半状态。
首次创建失败后，已持久化的鉴权开关保持要求鉴权，重启不会因 Key 表为空退回匿名模式。

## count_tokens

请求必须是 JSON 对象并提供 `messages` 数组；无效形状返回 Anthropic `invalid_request_error`/400。
保留既有 `messages: []` 本地估算兼容性，不增加上游调用或改变计费。

部署层的 Nginx 超时与服务 stderr 轮转见 [部署说明](../deploy/README.md)。
