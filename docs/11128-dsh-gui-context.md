# DSH 身份、GUI 环境说明与 11128

2026-10-21 的生产请求使用 `deepseek-v4.1-flash`、cn 站、Responses 流式入口，
会话头和既有 DSH 首句兼容规则均已执行，仍返回渠道校验类 11128。

经用户授权进行少量真实调用对照，确认本机 DSH 0.2.1-rc.2 自带的完整
`WEB_SURFACE_PROMPT` 是可复现触发条件。普通系统指令、60 个工具、推理等级、
输出预算测试可以成功；原故障账号去掉该段也可以成功。具体上游内部匹配规则未知，
不能据此将所有 11128 都归为同一问题，也不能据此认定所有第三方调用均不可用。

进一步参考并核对
[dsh-connect-workbuddy v4.15.1](https://github.com/dingminhua/dsh-connect-workbuddy/releases/tag/v4.15.1)，
发现 assistant 历史消息和数组的后续文本块同样需要覆盖。本项目另做真实短请求对照：
assistant 字符串开头、第二个文本块开头的原始 DSH 身份句均返回 11128，
相应中性句均成功。这不只是当前 system 提示词的问题，也会影响后续历史回放。

## 网关改动

在三协议共用的兼容步骤中，处理 system 和 assistant 的字符串及每个标准文本块：

- 每个文本开头的已知 DSH 身份句沿用中性前缀转换。
- GUI 中已确认的 221 字符两句开头按精确子串匹配，支持出现在文本中部。
- GUI 转换跳过代码围栏、行内代码和缩进代码。

仅将已知模板首句中的 `the DeepSeek Harness Web GUI` 改为 `a Web GUI`。
后续关于页面指代、浏览器上下文、构建、刷新、启动服务的全部指令逐字节保留。
GUI 后文、上下文和整个 system 的长度均不作为匹配条件，避免 DSH 增加或修改其他
指令后漏掉同一个已知触发片段。未知开头和未匹配的文字原样传递。

用户正文、tool 结果、工具参数、reasoning 和图像块不参与转换。
Messages 入口在文本块合并前处理 system/assistant 各块，避免后续块开头的位置丢失；
转换后仍执行幂等的共享步骤。宿主的会话文件不被修改。
仅记录固定规则名 `dsh_system_identity_prefix`、`dsh_assistant_identity_prefix` 和
`dsh_gui_context_identity`，不记录原文、会话标识或凭据。

这项兼容处理不改变客户端签名、授权身份或上游请求头。上游继续拒绝时仍如实返回
11128，不进行自动重放、换号补发或伪造成功。不能声称该处理赋予渠道授权。

## 验证

离线 HTTP 链路覆盖 Chat、Responses、Messages 的聚合与流式请求，检查转换后的
完整 system 和用户正文，验证继续拒绝时错误仍原样返回、不会额外调用上游。
单元边界覆盖样本摘要、GUI 后文变化、中段/多处匹配、CRLF、围栏/行内/缩进代码、
角色范围、后续文本块、幂等性和工具参数保留。新增历史回放 HTTP 链路覆盖三协议、
字符串/多文本块、聚合/流式及继续拒绝的情况。公共模板来源见
[样本说明](../testdata/dsh/README.md)。

真实调用已确认：只改该环境句、保留完整其余 system、60 个原有工具定义和 max 推理
等级的请求能够成功；原文同类请求此前稳定返回 11128。
真实验证没有重放完整用户历史，不能声称所有长期会话、DSH GUI 操作和上游策略变化
均已验证。生产部署和用户原会话复测仍是单独的步骤。

不需要修改 DSH 客户端或生产配置；代码合入后需要部署新网关二进制才能生效。

## 参考实现的取舍

v4.15.1 明确没有采用强行改成 WorkBuddy/CodeBuddy 身份的做法，并报告这会影响
模型的身份回答。本补丁采用中性描述，保留与用户交互所需的其余说明。
没有引入其零宽字符扰动及收费重试阶梯；已知片段在首个出站请求中完成兼容处理，
其他拒绝继续原样返回。不能将本补丁描述为未知渠道限制的通用规避或授权。
