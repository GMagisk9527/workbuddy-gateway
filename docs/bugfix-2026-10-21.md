# 2026-10-21 回归修复

基于 `cafbed0` 的离线复查确认并修复以下问题。所有验证使用合成数据、
本地 HTTP 服务或模拟 Transport，没有调用收费模型。

| 问题 | 修复后的行为 | 回归覆盖 |
| --- | --- | --- |
| 账本缺失后再次启动恢复零消费；无法归属的尾部记录重启后解除保护 | 将历史依赖和不完整状态持久化；重启、额度重置和压缩不会自动解除保护 | 连续重载、压缩、仅快照丢失、双文件丢失、旧 WAL 迁移、状态写入失败 |
| 编辑 Key 意外清空模型白名单 | 模型目录与原白名单取并集；加载中阻止保存，失败保留原选择；忽略迟到响应 | 目录缺模型、加载失败、加载中保存、切换/关闭编辑器、手动清空 |
| Responses 将输出截断标为完成 | `length` / `content_filter` 返回 `incomplete` 及原因；流式发送 `response.incomplete`；保留收到的内容与 usage | 非流式及快慢流式、残缺工具参数、正常 stop/tool_calls |
| 账号锁在响应头后提前释放 | 锁覆盖响应体读取；EOF、读取失败、关闭时只释放一次；排队可取消，拿锁后重查资格和令牌 | 多请求串行、重复 Close、失败释放、排队冷却/额度变化、续期等待取消、排队中令牌过期 |
| Messages 工具续轮丢失 thinking | 将已有 thinking 明文保留到上游推理字段；不从签名或不透明数据生成推理 | 两轮工具结果、enabled/adaptive/disabled、多个 thinking 块、不透明输入 |
| Chat 请求体 `null` 导致 panic | 返回结构化 HTTP 400 | 真实 HTTP 请求覆盖 null、数组、布尔、数字、字符串 |
| 删除 Key 后消费汇总减少 | 汇总包含匿名归档；额度重置不清除今日实际消费 | 删除、在途结算、重置、跨日、压缩及重启 |

账本尾部修复先重放历史，再以递增序号原子写入补偿，避免旧 reset 清除新补偿，
以及截断尾部但补偿尚未落盘的窗口。Windows 压缩通过独立写句柄截断 WAL。
删除后尚未压缩即重启时，旧快照中该 Key 的历史也会转入归档。
压缩在同一次账号表读锁内捕获活动 Key 与归档，避免并发删除导致两边都遗漏消费。

## 数据格式与升级

新增运行文件 `keyledger.state.json`，版本为 1，包含：

- `snapshotRequired`：历史已依赖快照；丢失快照不能当作空账本。
- `incomplete`：历史不完整；有限额 Key 保持拒绝准入。

正常首次启动自动建立状态文件。已有可信快照，或无快照但从序号 1 开始的完整
历史 WAL，可以保留用量升级。存在的状态文件和快照必须有受支持的显式版本；
`null`、空对象或错误版本会被拒绝，原文件保留。

旧安装若没有状态文件、没有快照，只有空 WAL 且已存在 Key，无法可靠区分零消费
与快照丢失，因此进入保护，需确认历史基线。不会自动把这种情况重置为零消费。

快照增加 `spentToday` / `spentDayKey`，使今日真实消费独立于准入额度重置。
旧快照只迁移其已保存的当日 Daily；旧版本 reset 已丢失的明细不作推算。

## 备份与异常恢复

应成组备份 `apikeys.json`、`keyauth.json`、`keyledger.snapshot.json`、
`keyledger.wal` 和 `keyledger.state.json`，保持快照与 WAL 属于同一可信备份集。

账本进入 `incomplete` 后，先停止服务并备份当前全部文件，再恢复一致的可信备份，
或逐笔核对并补齐实际消耗。只有历史完整、无法归属的消费已处理后，才可清除
快照的 `lostSettlements` 并将状态的 `incomplete` 设为 false；存在快照时保留
`snapshotRequired=true`。启动后核对用量及 `ledger.degraded`，再恢复流量。
删除状态文件或重置 Key 额度不能代替恢复。
