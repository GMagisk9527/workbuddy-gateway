# 按 Key 公平准入与请求诊断

`admission.fairQueue` 默认开启，显式 `false` 恢复全局 FIFO。总准入与前处理两个队列均按鉴权后稳定 Key ID 分组，同一 Key 内 FIFO；在有等待请求时优先在途较少的 Key，同等在途数量时按 Key 轮转。空闲时单个 Key 可用满全局名额，原有 Key 硬并发上限仍先执行。已经开始的请求/SSE 不会被抢占或缩容中断。

`maxWaitingPerKey` 是每个队列内单个已鉴权 Key 的等待上限，0（默认）取总等待上限的一半向上取整，最少1。总等待上限 `maxWaiting` 仍然有效，不为每个 Key 各分配一份全局队列。鉴权关闭且没有 Key 身份时沿用公共 FIFO，不接受客户端自报的身份创建队列；旧式共享 Key 作为一个调用方处理。取消/超时移除等待项，释放最后一个名额时清除对应活动计数。热更新保留已有计数与队列，不改变在途请求的结算覆盖范围。

```json
{"admission":{"maxActive":8,"maxPreparing":2,"maxWaiting":8,"fairQueue":true,"maxWaitingPerKey":0}}
```

两阶段仍共享原有准入等待期限，内存预算、账号调度及 Key 计费语义不变。公平队列不能立即收回已经借给某个调用方的长流名额；不同用户共用一个 Key 时不能按用户区分公平性。

管理员可用 `GET /admin/api/performance?trace=<X-Trace-ID>` 查询最近完成请求的分阶段耗时、状态及固定维度计数。接口沿用现有管理员鉴权；找不到、仍在执行、过期或被淘汰时返回404，格式无效返回400。普通性能聚合响应保持原结构。数据仅在内存中保留最近128条，查询窗口5分钟；重启清空。

记录仅含最多64字符的字母/数字/`-_.` Trace ID、固定协议名、HTTP状态、完成时间、各阶段耗时和固定计数，不记录 Key、模型名、账号、请求/响应正文、工具参数、URL查询串或错误正文。压缩代理返回的 `X-Compress-Trace` 用于本地记录，`X-Trace-ID` 用于对应网关记录；二者通常一致，服务端改变 Trace ID 时应使用代理记录中的 `gatewayTraceId` 查询。Trace ID只用于诊断，不承担鉴权、幂等或去重计费功能。

各阶段可能重叠或包含多次尝试，不能将所有耗时直接相加。代理看到的响应头等待包括上传、代理/CDN及模型处理，不能当作纯上传耗时；首个响应体字节也可能是SSE心跳，不能当作首个有效token。完整请求的服务端 `first_token` 仍使用原有有效增量定义。
