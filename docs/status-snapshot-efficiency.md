# 状态快照的锁隔离与写入合并

账号、模型和管理页面继续使用原有 `workbuddy-status.json` 格式，已有配置无需修改。
状态仍每3秒重新检查，账号变更、冷却结束、令牌过期和模型可用性等时间驱动变化
继续在下一次检查时写入；主动刷新调用仍立即检查。

采集阶段在账号锁下复制展示所需字段，深复制模型状态、积分包和凭据展示信息，
不复制账号内部锁，也不复制 Access Token。请求统计的账号状态采集仍沿原锁序进行。
签到身份摘要和资格在账号锁内从原账号计算，之后仅保留摘要与布尔值，不保留原账号引用；
锁外展示使用这些值，不通过省略了Token的副本重新判定资格，也不会调度签到请求。
模型汇总、目录/名单处理、签到展示读取、积分包排序、告警、JSON编码和文件I/O
在账号锁外执行，避免这些操作阻塞账号选号。副本不用于调度或发送模型请求。

快照内容相同的重复刷新只检查文件是否仍为上次成功写入的文件，不重复替换。
比较忽略更新时间和模型行的偶然排列顺序，告警数组使用稳定顺序；磁盘展示仍
保留原有模型目录顺序。进程只缓存一次成功写入的摘要和文件信息，不保留历史快照。

内容未变时每9秒更新一次完整快照心跳，低于已有管理页面15秒的过旧阈值；
正常每3秒轮询下，空闲写入频率由每3秒一次降为每9秒一次。仍执行每次状态检查，
不会因账号未主动变更而漏掉冷却、令牌、统计窗口、日期或签到状态的自然过期。
系统时钟回退会强制重新写入，不因负时间差一直跳过。

文件被删除、替换或元数据变化时会重建；不同工作目录不共用去重结果。
临时文件写入/重命名失败仍返回错误，成功后才更新去重记录，因此后续刷新会重试。
原有临时文件加原子重命名方式、告警状态和日志定位保留。

这仅优化展示快照。API Key账本的WAL、fsync、结算及故障保护不改变，
不会为减少磁盘写入而推迟消费记录持久化。
