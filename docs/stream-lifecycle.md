# 下游写入保护、在途指标与停机收尾

## 下游写入

三个模型 POST 路由及已有别名在入口固定本次请求的写超时快照。
每次 `Write` 和 `FlushError` 前单独设置截止时间，返回后清除；上游思考、
首增量等待和两次增量之间不保留写截止时间，持续输出的长回复没有总写时限。
聚合 JSON 的实际输出也使用同一保护。

- `downstream.writeTimeoutSeconds`：默认 30 秒；0 或省略使用默认，范围 0～3600。
- 审计及 Key 包装器通过 `Unwrap` 透传 deadline，通过 `FlushError` 传播刷新错误。
  写入、短写或刷新失败会取消请求；流式 guard 关闭当前上游响应体，并沿用原有释放、
  未完成响应和实测费用结算逻辑，不额外重试或伪造成功结束事件。
- HTTP/2 的写截止时间作用于当前响应流；测试覆盖慢流超时后，同连接另一个流正常完成。
- 实际 Go HTTP/1.1、HTTP/2 服务支持 deadline。自定义 ResponseWriter 如果没有
  deadline/Unwrap 能力，`ErrNotSupported` 会退回原行为；不会为每次写入另起 goroutine。
- 截止时间约束底层写入，不保证函数墙钟耗时精确等于设置值。直接由 Go 承载
  HTTP/1.1 TLS 时，标准库错误关闭 TLS 的 close_notify 可能另等约 5 秒；
  本地测试分别覆盖明文 HTTP/1.1、TLS HTTP/1.1 和 HTTP/2。反代终止 TLS 时，
  网关到反代的写入和反代到客户端的超时分别生效，仍需保留反代的发送超时。

热加载只影响后续请求，现有流保留进入时的写超时。

## 进行中的请求

管理页“用量与性能 → 链路分阶段性能”手动读取同一管理鉴权接口。
`protocols[].inFlight` 与完成请求的五分钟窗口分开：

- `active`：此协议当前尚未退出的模型请求，包含鉴权、准入和收尾。
- `activeStreams`：已建立流式会话且尚未结束的请求，聚合请求不计入。
- `waitingFirstToken`：已经进入出站调用，但尚未解析到首个有效文本、推理或工具增量。
  包含编码、连接、响应头及响应体等待；Responses 的前置事件不算模型增量。
- `writingDownstream`、`longestWriteMs`：读取时正在执行 Write/Flush 的请求数及最久耗时。
- `oldestRequestMs`：当前最老请求从入口到读取时刻的时长。
- `stages`：准备、准入、账号、凭据、首增量、响应处理、结算七个固定阶段的人数和
  本阶段最长停留；阶段人数互斥，流/首增量/写入计数可以重叠。

无在途样本的时长为 null，真实零值为 0。换号和首字节前重放仍属于同一个逻辑请求。
`runtime` 另给出全局准入/排队人数和上限、已保留的输入字节/预算、内存准入压力状态、
停机排空标记；这些全局值不受协议选择影响。压力状态沿用准入的迟滞结果，不等同于 RSS。
另包含输出预留字节、额外尝试并发和日志拒绝/采样计数，默认值和失败行为见
[资源预算说明](resource-budgets.md)。输出预算按小块申请，会短暂获取独立全局预算锁。

在途请求只串联自身已有的固定计时状态，结束或异常退出时移除，不保存历史明细、正文、
账号、模型或任意标签。SSE 写入只更新本请求的原子时间戳；状态切换和手动快照使用独立锁，
不在每个增量上获取全局聚合锁。快照是读取时的近似现场，不是多个子系统的原子事务。
停机拒绝发生在业务审计之前，不进入完成请求窗口；就绪与存活探针也不计入模型指标。

## 停机

`SIGTERM`/中断或监听异常后，两端口共享同一个排空状态与取消源：

1. 拒绝新业务请求，返回 503 和 Retry-After，Messages 使用 overloaded_error。
   停止配置热加载及签到，关闭监听及空闲连接。
2. 在 `server.shutdownGraceSeconds` 内等待现有请求自然完成，默认 120 秒。
3. 期限届满或监听关闭失败时，取消全部在途请求并关闭连接。
4. 再等待 `server.shutdownCleanupSeconds`，默认 15 秒。业务 handler 的追踪覆盖
   外层审计和同步 Key/WAL 结算；连接关闭不代表结算已经结束。
5. 所有业务 handler 退出后，沿用原有统计落盘退出。清理超时会明确记录
   “结算收尾未确认”，不会报告安全完成；不会无限等待一个不响应取消的 handler。

两个配置省略或 0 使用默认；自然完成等待范围 0～3600 秒，清理范围 0～300 秒。
端口热切换后，新监听与仍承载旧连接的服务器共享上述就绪、取消和请求追踪；
停机同时排空当前及已退役的监听，仍等待旧连接的同步 Key/WAL 结算完成。
停机开始时固定最新配置快照。服务管理器（OpenRC/systemd/容器）的强杀等待必须大于
这两个期限之和，并为连接关闭、最终落盘留出余量，否则管理器仍可能提前杀进程。
本改动不会自动修改现有部署配置，也不保证强杀或断电时的在途响应能恢复。

实际监听上的 `GET/HEAD /readyz` 无需 Key，仅表示该进程是否仍接收新请求：正常 200，
排空 503，不公开账号、密钥或配置，也不探测上游。`/health`、`/ping` 保留原有存活语义。
单机重启仍有服务切换空窗；排空不会实现跨进程迁移一个已经开始的 SSE。

## 验证

本地测试覆盖刷新错误穿透两层包装、读写超时不误杀思考间隔、三个协议快慢路径实测费用
保留、慢客户端释放准入/账号名额、HTTP/2 同连接隔离、在途排队与首增量现场、取消与
panic 清理、并发快照、自然完成、强制取消后真实 WAL 等待和超时报告。均未调用真实模型。
