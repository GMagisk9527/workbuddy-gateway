# 本地计数与隔离安全重试

## count_tokens

`/v1/messages/count_tokens` 始终在本地估算，不调用模型或图片 URL，也不产生账号消耗。
响应形状仍为 `{"input_tokens":数字}`。计数沿已解析 JSON 累加，不再拼接整份 system、历史和工具参数，
也不重新序列化完整工具列表。普通文本保留原 CJK 约1 token/字、其他字符约4字符/token 的估算规则。

覆盖文本、会回传的 thinking 明文、工具名/输入/定义、工具结果中的文本和图片。签名和不回传的
redacted_thinking 不作为模型正文计算；不支持的文档等块仍按原请求校验拒绝。
嵌入图片只解码最多64KiB的头部，使用尺寸估算，不解码像素、不构造完整 data URL；
可识别 PNG/JPEG/GIF 头部，其他格式、无效/超限头部及远程 URL 统一使用1600 token 的回退估算。
尺寸估算为最长边缩到不超过1568后，面积除750向上取整，并限制单图1～1600。
这些数值是通用启发式，不能视为任意上游模型的精确图片 tokenizer。

可将以下字段合入原配置，以同模型、相近内容组成的真实 usage 人工校准本地估算：

```json
{"tokenEstimation":{"modelMultipliers":{"your-model-id":1.1}}}
```

倍率默认1，允许0.25～4，模型名不区分大小写，最多128项；规范化后重复、非法名字或倍率会拒绝整个配置。
该设置可热加载，删除配置即恢复1。不同模型的分词器、协议转换和网关注入内容都可能造成偏差，
这里不自动从 usage 学习，也不改变真实请求的内容、上下文上限或计费；最终用量仍以真实 usage 为准。
结果按请求累计后取整，并限制在32位有符号整数范围内，避免不同架构溢出。

## 安全重试的连接隔离

原有请求头/体可能已发出的判定、额外尝试预算、重试次数、鉴权快照和结算语义保留。
只有原策略允许的安全重试使用新连接；每次重试复制现有客户端策略及受管 Transport 配置，
保留代理、TLS验证、HTTP/2、Cookie、重定向和超时，使用自身独立的连接池，不清理共享池中的健康空闲连接。
临时池只用于该次尝试，错误、响应读完/关闭或取消时清理，不为未来请求保留连接。

内置热配置 Transport、标准 Transport 和标准默认 Transport 支持这种隔离。
任意自定义 RoundTripper 没有通用的安全克隆接口时继续沿用自身实现和 `Request.Close` 语义；
其连接池由实现者负责，网关同样不会调用其共享 CloseIdleConnections。
配置热加载导致的 Transport 替换仍按原逻辑回收旧空闲连接，属于独立的配置变更行为。
