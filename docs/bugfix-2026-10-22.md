# 2026-10-22 审查回归修复

基于 `5b47114`，修复离线审查确认的七处问题。请求均使用合成数据、
本地 HTTP 服务或故障写入器，没有调用收费模型或读取生产凭据。

| 问题 | 修复后的行为 |
| --- | --- |
| 客户端断流丢失已解析的 usage | 三协议在返回前保留已获取的真实费用，及时关闭上游；未收到费用仍按未知处理 |
| 并发位在结算前释放 | 准入并发位覆盖结算，下一请求看到已更新的额度；外层审计不重复结算 |
| 删除 Key 与结算交错重复归档 | 结算更新与密钥成员关系保持一致，同一消费只进入活动用量或匿名归档一次 |
| 跨文本块的 Markdown 代码被改写 | GUI 兼容处理保留跨块代码上下文，文本块顺序、附加字段和代码原文保持不变 |
| Messages 聚合丢失正文 | 按创建顺序保留全部正文、thinking 和工具块，避免重新打开正文时覆盖旧缓冲 |
| 鉴权元数据缺少结构校验 | 独立开关仅接受显式布尔值；非法开关保持要求鉴权，非法密钥表拒绝加载 |
| 规范化后的 force 重复追加 | 比较提示词的实际兼容形式，重复执行不再追加同一配置指令，配置原文不变 |

## 验证

回归测试先在旧代码上复现失败，再验证修复。重点覆盖：

- Chat / Responses / Messages 的快慢流式路径，费用为正数、明确为零和缺失三种情况。
- 断流及时关闭上游、不补成功结束事件，真实费用仅结算一次。
- WAL 写入等待期间的新请求准入、删除与结算交错、压缩及重启。
- 三协议的 system / assistant 跨块代码，Anthropic 合并前处理，以及普通用户正文保护。
- Messages 的正文、thinking、工具块交错及工具参数拼接。
- 鉴权开关与密钥表的非法文档、合法旧数据、显式关闭及首次缺文件行为。
- 配置提示词兼容处理的幂等性。

执行全量 `go vet ./...`、`go test ./...`、`go test -race ./...` 并构建
Linux amd64；实际结果记录在 PR 中。

## 数据与部署

不变更凭据、配置或账本格式，不重置 API Key 或额度，不重写历史消费。
非法持久化文件不会被自动覆盖为空文件。
若旧版本已经将重复归档写进快照，需要另行核对可信 WAL 和备份；本修复防止再次发生，
不会猜测并扣减既有历史数据。

本补丁没有部署或重启生产服务。合并后部署新二进制才能使线上行为生效。
